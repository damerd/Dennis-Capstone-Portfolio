Project Overview

ClaimIntel is an AI-powered claims intelligence platform designed to help insurance professionals organize claim information, identify missing evidence, evaluate liability and exposure, and generate structured reports that support professional judgment. The goal is decision support, not decision replacement.

I selected ClaimIntel for my capstone because it gave me the opportunity to combine my professional claims experience with the technical skills I developed throughout the Computer Science program. Instead of creating three unrelated projects, I used one working application and improved it across software design and engineering, algorithms and data structures, and databases.

Enhancement Progression

1. Software Design & Engineering

The first enhancement focused on making ClaimIntel easier to maintain and extend. The original application worked, but too much responsibility was concentrated inside large page components. I separated claim-review orchestration, configuration, document processing, validation, error handling, saved-review operations, and reporting into focused modules and services. The main NewClaimReview page was reduced from roughly 483 lines to about 223 lines, and the application gained a canonical report model so the screen, PDF, Word, text, and clipboard outputs could rely on one source of truth.

This enhancement also introduced clearer failure states, advisory claim-readiness validation, reusable components, stronger project documentation, and production-build verification. The biggest lesson was that working software is not automatically well-engineered software; structure matters because future changes become much safer when responsibilities are clearly separated.

2. Algorithms & Data Structures

The second enhancement added a deterministic evidence-validation pipeline so ClaimIntel could evaluate information in a way that was more transparent, repeatable, and testable. The enhancement included normalization and tokenization, an inverted index, evidence matching, detection of missing and unsupported information, deduplication, severity prioritization, weighted readiness scoring, Sets and Maps, and a stable max-priority queue.

Testing edge cases showed me that visible output is not enough to prove an algorithm is correct. Cases involving duplicate identifiers, conflicting jurisdictions, negative evidence, monetary values, equal-priority ordering, and short input forced me to make the rules more precise. The result was a stronger balance between industry knowledge and software rules that stop when the available evidence does not support a conclusion.

3. Databases

The database enhancement moved ClaimIntel beyond storing most information in a single claim-review record. I introduced related data entities for ClaimReview, ClaimAnalysis, ClaimDocument, ClaimReviewHistory, and AuditLog, along with repository and compatibility layers that control how data is written and retrieved.

The enhanced design includes normalized claim numbers, validation and writable-field controls, version tracking, history records, repository-backed search and filtering, soft deletion and restoration, and sanitized audit metadata. The Saved Reviews and Database History interfaces make these changes visible instead of leaving the database work hidden in the code. I also created a database test script with 13 assertions to verify the behavior.

How the Enhancements Fit Together

Although each milestone focused on a different computer science category, the improvements are connected. The software-engineering refactor created cleaner boundaries for new functionality. Those boundaries made it easier to introduce deterministic evidence-processing algorithms without burying more logic inside the interface. The database enhancement then provided a stronger way to preserve the structured information and analysis produced by those workflows.

Together, the enhancements demonstrate how architecture, algorithms, persistence, testing, security, and communication work as parts of one complete computing solution rather than as isolated skills.

Security and Professional Responsibility

ClaimIntel handles information that could be sensitive in a real claims environment, so security was treated as a design concern rather than an afterthought. The enhanced application uses validation, controlled writable fields, user-based record access through the underlying platform, sanitized audit metadata, version history, and soft deletion instead of immediately destroying records.

The capstone version is an academic and developmental system, not a production-ready platform for regulated insurance data. That distinction matters. A secure development mindset includes recognizing the limits of a system and avoiding claims that the current implementation cannot support.
